# Verso V3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Livrer la V3 de Verso (notes et sauvegarde) jusqu’à ce que tous les « Critères d’acceptation V3 » de `docs/SPEC.md` soient cochés.

**Architecture:** Les deux modules restent. `:core` reçoit la logique pure : position d’un passage dans le texte d’un chapitre et fusion des surlignages (`core.notes`), fichier Markdown exporté, validation d’une sauvegarde (`core.backup`), et deux événements de sélection dans la machine à états. `:app` ajoute la table Room `highlights` (migration 2 → 3), la sélection et les décorations Readium dans `FragmentReaderController` / `ReaderSurface`, un `HighlightCoordinator` à côté de `ReaderViewModel`, l’écran « Notes et surlignages » (même composable en surcouche du lecteur et en route depuis la fiche), et la sauvegarde zip (`backup/`) avec son écran dans les Paramètres.

**Tech Stack:** celle de la V2 (Kotlin 2.4.20 intégré à AGP 9.4.1, Compose BOM 2026.09.00, Material 3, Navigation 2.10.2, Room 2.8.5, DataStore 1.2.1, Coil 3.6.3, Readium kotlin-toolkit 3.4.0, kotlinx.serialization, JUnit 4, Truth, Turbine, Robolectric 4.17, Roborazzi). Aucune dépendance nouvelle ; `java.util.zip` pour le zip.

**Spec:** `docs/SPEC.md` (« V3 — Notes et sauvegarde », « Décisions de la V3 », « Critères d’acceptation V3 ») et `docs/superpowers/specs/2026-09-30-verso-v3-design.md`. Maquettes : `docs/design/screens/3.04` à `3.07` (PNG) et `docs/design/html/3.04` à `3.07` (libellés exacts, mesures). Les maquettes 3.01 à 3.03 (PDF) sont hors V3.

## Décisions prises en rédigeant le plan

À reporter dans `docs/SPEC.md` (« Décisions de la V3 » et « Historique ») au commit de l’étape concernée.

- **Passage dans le texte du chapitre** (17) : la position d’un surlignage se retrouve dans le texte brut du chapitre (`ChapterText.plainText`, espaces normalisés) par son texte et ses 32 caractères de contexte avant et après. Le chevauchement se décide sur ces plages de caractères ; le surlignage fusionné reçoit un locator reconstruit (texte, contexte, progression du début), sans sélecteur CSS : Readium le retrouve par le texte. Un passage introuvable n’est jamais fusionné (il est ajouté tel quel).
- **Chapitre enregistré avec le surlignage** (17) : le chemin du sommaire (`chapterPath`, par exemple `["Deuxième partie", "I"]`) est enregistré dans la ligne `highlights`. La liste et l’export n’ont pas à rouvrir l’EPUB.
- **Machine à états** (17) : deux événements, `SelectionStarted` et `SelectionEnded(position)`. Entre les deux, `Displayed` ne fait que mettre à jour l’affiché, `GestureEnded` est ignoré ; `SelectionEnded` prend l’affiché comme nouveau point de départ, sans effet (ni lecture, ni carte, ni mots lus). Le défilement automatique pendant que l’on tire une poignée ne compte donc jamais.
- **Barre de sélection** : les poignées d’Android sont des fenêtres à part que Compose ne voit pas ; le texte affiché dans la barre est relu toutes les 300 ms pendant la sélection (`ReaderGestures.SELECTION_POLL_MS`) et relu une dernière fois au moment de l’action.
- **« Notes et surlignages » depuis le lecteur** (19) : surcouche du lecteur, comme la recherche (2.06), pour que « aller au passage » soit un saut dans le même lecteur (carte « Revenir »). Depuis la fiche : route `NotesRoute`, et toucher un élément ouvre le lecteur avec `ReaderRoute.highlightId` (saut au chargement).
- **5ᵉ outil** (19) : la rangée d’outils passe déjà à deux colonnes puis une quand les libellés ne tiennent plus (`ReaderToolbar`, V2) ; « Notes » tient donc à 200 % sans coupure, la barre garde ses cinq outils.
- **Sauvegarde** (20) : les réglages sont copiés clé par clé depuis DataStore (type compris), sauf la carte « Dernière sauvegarde », propre au téléphone. Les chemins des fichiers sont réécrits vers le stockage du téléphone qui restaure.
- **Libellés absents des maquettes**, proposés et à confirmer par Maxime à la fin de l’étape : « Passage copié » (17), « Surlignage » (titre de la feuille d’un surlignage touché, 17), « Modifier la note » (titre de la feuille de note sur un surlignage annoté, 18), « Surlignage supprimé » (18), « Aucun surlignage pour l’instant. Sélectionnez un passage pendant la lecture pour le surligner. » (19), la ligne d’en-tête du Markdown (19), « Aucune sauvegarde pour l’instant », la confirmation de restauration et les messages d’échec (20).

## Review Focus

1. **Sélection et machine à états** : appui long puis poignée tirée jusqu’en bas de l’écran (défilement automatique), puis toucher ailleurs pour annuler — la position de lecture ne bouge pas, pas de carte, pas d’affichage de la barre de lecture, pas de mots comptés. → `ReadingPositionTrackerTest` (17.3) et `FragmentReaderControllerTest` (17.4).
2. **Surlignage qui recoupe plusieurs surlignages**, ou qui en contient un entièrement, ou qui est contenu dans un autre ; passage répété plusieurs fois dans le chapitre (même texte ailleurs) ; passage introuvable dans le texte brut (entités, balises) — un seul surlignage reste, notes dans l’ordre du texte, jamais de perte de note ; l’occurrence choisie est celle dont le contexte correspond. → `HighlightMergeTest`, `TextQuotesTest` (17.1), `HighlightCoordinatorTest` (17.6).
3. **Base de la V2 sur le téléphone** : la migration 2 → 3 garde livres, positions, états, défilements et sessions ; supprimer un livre supprime ses surlignages (cascade). → `VersoDatabaseMigrationTest`, `HighlightDaoTest` (17.2).
4. **Restauration qui échoue au milieu** (fichier tronqué, zip qui n’est pas une sauvegarde, format plus récent, EPUB manquant dans le zip, espace disque) : bibliothèque, fichiers, réglages intacts, dossier temporaire effacé, message. → `BackupRestorerTest` (20.4).
5. **Note vide ou blanche, note très longue, passage très long** (plusieurs paragraphes) : « Enregistrer » avec une note vide crée un surlignage sans note ; la note longue défile dans la feuille à 200 % ; la barre de sélection montre le début du passage sans couper la mise en page. → `HighlightCoordinatorTest` (18.1), `NoteSheetTest` (18.2), `SelectionBarTest` (17.7).

```kotlin
// core/src/main/kotlin/com/maximebier/verso/core/notes/TextQuotes.kt   (tâche 17.1)
package com.maximebier.verso.core.notes

/** Passage et son contexte, comme `Locator.Text` de Readium (highlight, before, after). */
data class TextQuote(val highlight: String, val before: String = "", val after: String = "")

object TextQuotes {
    /** Caractères de contexte gardés avant et après un passage reconstruit. */
    const val CONTEXT_CHARS = 32
    const val PREVIEW_CHARS = 48
    /** Espaces (dont insécables et retours à la ligne) réduits à une espace, bords coupés. */
    fun normalize(text: String): String
    fun collapse(text: String): String          // comme normalize, sans couper les bords
    fun preview(text: String, maxChars: Int = PREVIEW_CHARS): String   // barre 3.04 : « … » après un mot
    /**
     * Plage [start, endExclusive) du passage dans [chapterText] (déjà normalisé). Plusieurs occurrences : celle dont le
     * contexte (fin de `before`, début de `after`, normalisés) correspond le mieux. null si le passage est absent.
     */
    fun locate(chapterText: String, quote: TextQuote): CharSpan?
    /** Passage de [chapterText] à [span], avec son contexte. */
    fun quoteAt(chapterText: String, span: CharSpan): TextQuote
}

/** Plage de caractères [start, end) ; start < end. */
data class CharSpan(val start: Int, val end: Int) {
    fun overlaps(other: CharSpan): Boolean = start < other.end && other.start < end
    fun union(other: CharSpan): CharSpan = CharSpan(minOf(start, other.start), maxOf(end, other.end))
}
```
